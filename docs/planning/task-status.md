## Incident majeur résolu (TASK-003-03-03) — perte de données sur écritures rapprochées

Deux écritures rapprochées (ajout de 2 périodes en quelques secondes) provoquaient une **perte silencieuse de la première période**. Cause racine : cache compilé de Grav sur `Page::header()` (`CompiledMarkdownFile`, `cache/compiled/files/`), non invalidé de façon fiable entre requêtes rapprochées sous PHP-FPM. Trois tentatives de correction insuffisantes ou contre-productives (`clearstatcache()` seul, `Cache::invalidateCache()`, `Cache::deleteAll()` — cette dernière corrigeait la perte de données mais cassait la validation des nonces). **Correction retenue** : `Availability::getUnavailablePeriods()` lit désormais directement le fichier source sur disque (contournant le cache compilé), au lieu de passer par `Page::header()`. Détails complets dans `docs/model/disponibilites.md`.

**Incident secondaire résolu en cours de diagnostic** : le compte `proprio-gite-1` avait un hash de mot de passe corrompu (tronqué de 9 caractères, cause exacte non identifiée) empêchant toute connexion — corrigé via `bin/plugin login change-password` (outil officiel, pas d'édition manuelle du hash). Protection anti-brute-force de Grav (`max_login_count: 5`/10 min) également déclenchée par les tests répétés de cette session — cache `cache/login/login_attempts` vidé (donnée de test, pas une donnée réelle).
